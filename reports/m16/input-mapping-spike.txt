What this run does and does not establish
  The device half is settled by the guest itself: Linux enumerates
  "QEMU Virtio MultiTouch" only when it is configured, so the device
  reaches the guest kernel.

  Acceptance is NOT discriminating: QEMU accepted the same events with no
  multitouch device attached, and still reported MaxSlots = 10.
  So "QEMU accepted them" is not evidence of delivery, and is not claimed as such.

  UNVERIFIED: the coordinates a guest ultimately reads. The Linux fixture
  has no evdev interface — its initramfs runs no udev, the handler is
  absent, /sys/class/input/inputN has no eventN and /dev/input does not
  exist — so nothing in the guest can observe a touch. That waits for an
  Android guest (Milestone 4).
